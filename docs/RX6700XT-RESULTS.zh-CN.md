# RX 6700 XT：序章实机验证

**2026-11-25，Windows，AMD Radeon RX 6700 XT（RDNA 2，12 GB），Adrenalin 26.11.2。** 本报告描述本机同一进程的实际运行，不是上游 README 的转载，也不是离线 DXIL 验证或 WARP 测试。

## 运行条件

- 代码：[fxceless/victory-fork #98](https://github.com/fxceless/victory-fork/pull/98)，固定 `e8cad1e1c4c840f1abcc324c1a2cdc5f98f5f14b`。该 PR 在大资源视图堆上采用百万槽上限和末尾的空描述符，避免着色器直接索引访问超出限额。它不是光追实现，也不负责还原缺失纹理。
- Series X 配置、diagnostics 构建（启用诊断功能的优化构建）、冷着色器与 PSO 缓存；`VICTORY_PORTABLE_HEAP=1`、`VICTORY_SHADER_LOOP_LIMIT=256`、`VICTORY_D3D12_DRED=1`。没有使用 [Issue #3](https://github.com/fxceless/victory-fork/issues/3) 的管线跳过清单。实际运行未设置固定时间上限，保留内存、显存等保护。
- 游戏请求 **1,245,184** 个资源视图槽；实局日志确认走了 #98 的百万槽限额分支。一次独立、未提交任何 GPU 工作的 D3D12 能力检查，还确认这张卡能分配 1,000,001 槽的堆；该检查不能代替实局。
- 本分支公开的可选 `VICTORY_PRESTREAM_IMAGES=1` 仅在指定帧保存正常呈现的画面，不打开逐绘制的详细日志。它不改变场景材质或渲染算法。外部采集、进程守护和本地路径兼容逻辑不随这里的源码分发；这里不是对当时可执行文件的逐字节复现包。

## 同一局里实际发生了什么

| 阶段 | 可复核的观察 | 不能据此推出什么 |
|---|---|---|
| 片头后黑屏 | #2047–2049 三张 1920×1080 正常呈现原帧全黑；#2100–2102 全图最高通道值仅 1/255。之后曾正常显示离线网络提示。 | 早期一张黑帧不等于之后一直黑；提示框也不是 3D 世界。 |
| 暂停菜单 | #2600–2602 可读到 `PROLOGUE`、左侧导航、`Retry Checkpoint` 和 `Restart Mission`。之前另一构建曾出现相同两行缺字。 | 菜单后面的模糊背景不能单独作为可见世界证据。 |
| 序章院子及输入 | #3000 和 #3001 两张连续正常呈现原帧均有近处人物、院内其他人物、建筑与远处瞭望塔；本机测试者另外确认按键可操控。 | 输入由测试者确认，不是从两帧的像素变化推断。没有据此宣称整个游戏可玩。 |
| 走廊 | #4096 走廊墙面有纹理、门洞较亮，但人物头身轮廓/躯干局部仍不完整，暗部明显不足。 | 不能由截图直接确定是蒙皮缓冲、贴图还是间接光照中的某一项。 |

**性能：** 首组院子原帧之后的一段完整统计窗口共呈现 **581 帧 / 597.575 秒 ≈ 0.972 FPS**（不是峰值或整个流程的均值）。黑屏采样段 #1750–2102 的在建 PSO 数中位约 **1,043**，记录线程每帧等待管线的中位约 **500.4 ms**；而从院子至走廊，一百八十九次采样中有一百八十二次 PSO 在建数为零，模型与暗部缺陷仍存在。同期到期的索引纹理槽数中位约 9,693；槽数并不等于独立纹理数，也不能对应某个角色的脸或衣服。

## 结论与下一步

这是 **#98 开启配置至少能走到哪里** 的实测基线。没有同 EXE、同剧情下的 OFF 实局配对，也没有证据表明本机此前的掉卡与上游报告的故障地址完全相同。不能把所有改善单独归功于 #98，更不能把晚加载作为所有画质异常的解释。

后续将材质翻译、蒙皮输入、光照和纹理驻留分别测试；同一机位、同一人物的正常原帧决定是否有视觉改善。仅“着色器可翻译/通过 DXIL 校验”或“宿主管线已建成”不算画质修复。
